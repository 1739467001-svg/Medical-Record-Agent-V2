# 接口与字段映射说明

> 对应方案 6.1 交付物"接口与字段映射说明"与 2.3"标准化空白模板（DataSource/BindingPath）"。
> 版本 V1.0 ｜ 面向：信息科联调工程师 / 大模型工程师
> 本文档定义 AI 病历智能体与院内系统之间的三类接口，以及生成内容到院内模板字段的映射关系。

## 一、接口总览

| 接口 | 方向 | 触发时机 | 演示版现状 |
|---|---|---|---|
| I-1 患者与诊疗数据拉取 | 系统 → HIS | 接诊第一步（患者核对） | 以院内导出数据（xls/XML 整理为 `data.js`）模拟 |
| I-2 病历草稿回填归档 | 系统 → HIS/EMR | 医师签名归档后 | 生成 Markdown + 字段绑定清单（留痕可查），未真正写回 |
| I-3 语音转写 | 系统 → ASR 引擎 | 问诊录音 | 演示引擎/浏览器引擎已通；讯飞/阿里 WS 通道待密钥（系统设置页配置即就绪） |

## 二、I-1 患者与诊疗数据拉取（约定接口）

```
GET /his/api/patient/{patientId}?visitId={visitId}
Authorization: Bearer <token>
```

响应结构（按院内 HIS 实际数据字典裁剪，键名以 `data.js` 为准）：

```json
{
  "patient": { "id", "name", "sex", "age", "marriage", "birthplace", "ward", "admittedAt", "visitNo", "allergies" },
  "labs":    [ { "item", "code", "result", "unit", "flag(H/L)", "range", "time" } ],
  "orders":  [ { "text", "dose", "route", "freq" } ],
  "vitals":  { "T", "P", "R", "BP" },
  "history": [ { "date", "dept", "dx", "docs[]" } ]
}
```

演示数据源对照：`检验结果.xls`（ABNORMAL_INDICATOR=H/L）、`医嘱.xls`（ORDER_TEXT/DOSAGE/ADMINISTRATION/FREQUENCY）、`生命体征.xls`（VITAL_SIGNS/VITAL_SIGNS_CVALUES）、病案 zip 内 XML 文书（`XInputField` 的 ValueBinding）。

## 四、I-2 归档回填（约定接口）

```
POST /emr/api/archive
Authorization: Bearer <token>
Content-Type: application/json

{
  "patientId": "1000540846",
  "visitId": 3,
  "docType": "admission | firstCourse | discharge | outpatient",
  "archiveId": "AR87303818",
  "signedBy": "张岩",
  "signedAt": "2026-10-03 01:28:23",
  "fields": { "Admission.ChiefComplaint": "…", "...": "…" },
  "auditTrail": [ { "action", "time", "doctor", "detail" } ]
}
```

要点：
- 每字段值在系统内携带 `source(his/dlg/norm/miss) + confidence + evidence`；回填包仅包含**医师已确认**的字段（黄色未处理字段会被质控拦截，不会进入回填包）；
- `auditTrail` 为全程留痕（登录/录音/修改/留空/归档），随包提交满足方案 3.4 审计要求；
- 回填后院内系统返回归档号，系统记录对应关系供追溯。

## 五、I-3 ASR 引擎接入（可替换模块）

引擎接口（`asr.js`）：

```js
startASR(dialogue, {
  onTurn(turn, i),            // 一句话开始
  onProgress(text, i),        // 转写增量
  onDone(), onError(msg),
}) => { stop() }
```

- **演示引擎**：已实现（时间驱动追帧调度，防后台节流）；
- **浏览器引擎**：已实现（Web Speech API）；
- **讯飞实时语音转写**：密钥经"系统设置"登记即就绪，WS 通道（wss://iat-api.xfyun.cn/v2/rtasr，签名 = HmacSHA1(apiKey + ts, apiSecret)，含医疗热词表）M2 挂接；
- **阿里云智能语音交互**：密钥登记即就绪，Token 换取 + WebSocket 通道 M2 挂接。

热词定制：医院提供药品名/检查名清单（可从 HIS 字典导出），按引擎热词规范注入。

## 七、BFF 服务端接口（M2.0 已实现并实测）

前端与 BFF 同源（8801），密钥只存 `data_server/config.json`（0600），GET 永不回显明文。

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/health` | GET | 掩码状态（engine / 各引擎 hasKey 布尔 / auditDB），不含密钥明文 |
| `/api/config` | GET / POST | GET 掩码状态；POST 合并保存（**留空字段=保持服务器现值**），写入 config.json（0600） |
| `/api/audit` | GET / POST | 留痕批量写入与分页读取（SQLite `audit_logs`，前端写后即报、启动即拉合并） |
| `/api/archives` | GET / POST | 归档写入（INSERT OR REPLACE）与读取（`archives`） |
| `/api/llm/test` | POST | 服务端代理探测 `{baseUrl}/models`（消除浏览器 CORS） |
| `/api/llm/chat` | POST | 服务端代理 `{baseUrl}/chat/completions`（M2.1 生成智能体替换走此通道） |
| `/api/asr/sign` | POST | 讯飞实时转写签名 `base64(HmacSHA1(apiSecret, apiKey+ts))` **服务端计算**；阿里云 Token 流程 M2.1 挂接 |
| `/api/demo/clear` | POST | 清空演示留痕与归档（两表 DELETE） |

实测记录：签名向量本地复算 MATCH；代理连通（/models 200、chat 桩往返）；入库持久化（清浏览器缓存并重启后归档仍在）。
