# 部署与运维手册（MVP 演示版）

> 对应方案 6.1 交付物。版本 V1.0 ｜ 面向：信息科 / 系统管理员
> 正式版部署（GPU 服务器、私有化大模型）另行编制，本手册覆盖演示与试用环境。

## 一、环境要求

| 项目 | 要求 |
|---|---|
| 服务器 | 任意可运行 Python 3 的主机（演示版无需 GPU） |
| 浏览器 | Chrome / Edge 最新版（语音识别功能需 Chrome 内核） |
| 网络 | 院内局域网即可；无需访问公网 |
| 磁盘 | < 100MB（含门诊演示音频 37MB） |
| 数据库 | 默认 SQLite（无需安装）；生产可选 MySQL 5.7+/8.0（驱动已随项目打包） |

## 二、部署步骤

```bash
# 1. 拷贝 medagent 目录到服务器任意路径
# 2. 启动（默认 8801 端口）
cd medagent
bash start.sh            # 或指定端口：bash start.sh 9000

# 3. 验证
curl http://localhost:8801/index.html   # 返回 HTML 即成功
```

浏览器访问 `http://<服务器IP>:8801`，选择医生卡片登录即可。

## 三、日常运维

- **启动/停止**：`start.sh` 前台运行，`Ctrl+C` 停止；生产建议用 systemd 托管（模板见下）。
- **数据备份**：留痕/归档在服务端数据库（默认 SQLite，可切 MySQL），定时备份见第八章；浏览器 localStorage 仅为前端会话缓存，清缓存不丢服务端数据。
- **日志**：HTTP 访问日志输出到启动终端；业务留痕见系统内"留痕与审计"页，可导出核对。

systemd 模板（`/etc/systemd/system/medagent.service`）：

```ini
[Unit]
Description=AI MedAgent BFF Server
After=network.target mysql.service

[Service]
WorkingDirectory=/opt/medagent
ExecStart=/usr/bin/python3 server.py 8801
Restart=on-failure
User=www-data

[Install]
WantedBy=multi-user.target
```

## 四、系统配置管理

- **入口**：侧栏"系统设置"。
- **ASR 引擎密钥**：选择引擎（讯飞/阿里）→ 填入 AppID/APIKey 等 → 保存。保存后接诊录音页对应引擎芯片立即显示"就绪"。
- **大模型 API**：填写 OpenAI 兼容的 Base URL 与 API Key，点"测试连接"验证可达性（浏览器直连失败多为 CORS，正式版经服务端代理）。
- **脱敏开关**：对外演示前开启，患者姓名全部化名显示。
- **配置存储**：`localStorage['medagent_cfg']`；正式版迁移至服务端加密存储，接口不变。

## 五、数据安全与合规要点

1. 演示数据含真实患者信息（已截图脱敏的系统除外），**禁止部署到公网**，禁止外传目录与数据文件；
2. 对外演示务必开启脱敏开关；
3. 演示结束用"系统设置 → 清空演示归档与留痕"清理业务数据；
4. 正式版安全基线（传输/存储加密、角色权限、审计入库、私有化部署）按方案 4.5 执行。

## 六、故障排查

| 现象 | 处置 |
|---|---|
| 页面打不开 | 确认端口未被占用（`lsof -iTCP:8801`），换端口重启 |
| 语音引擎灰色"未配置" | 到系统设置填写该引擎密钥并保存 |
| 大模型测试失败 Failed to fetch | 目标服务未开 CORS；属预期，正式版走服务端代理 |
| 刷新后接诊进度回退 | 会话恢复机制生效：退回"问诊录音"步时转写内容仍在，直接点启动生成 |
| 归档按钮灰色 | 有黄色缺失字段未处理，回草稿页补填或"确认留空" |

## 七、M2.0 服务端模式（BFF，已启用并实测）

`start.sh` 现默认启动 `server.py`（BFF，纯 Python 标准库）；找不到时自动回退纯静态模式。

- **数据目录 `data_server/`**（备份即拷贝本目录）：
  - `medagent.db`（SQLite，默认后端）：`audit_logs` 留痕表、`archives` 归档表；`backups/` 为定时备份输出；
  - `config.json`（权限 0600）：ASR/大模型密钥与数据库后端配置，**仅存服务器，浏览器不落明文**；删除该文件即回到"未配置"状态；
  - 存储后端可选 MySQL（迁移/切换/备份详见第八章）。
- **端口**：8801（BFF 与静态资源同源，无需 CORS）。
- **清空演示数据**：系统设置 →"清空演示归档与留痕"（POST `/api/demo/clear`，同时清空两表）；或停服后删除 `data_server/` 整目录。
- **离线降级**：BFF 不可达时前端自动回退本机 localStorage 模式（侧栏显示"本机演示模式"），功能完整、数据仅存本机。
- **健康检查**：`GET /api/health`（掩码状态，不含密钥明文）。
- **开发专用**：`tools/mock_llm.py`（8899，OpenAI 兼容桩）仅用于无真实模型时验证代理链路，**生产环境禁止启动**。

故障排查追加：

| 现象 | 处置 |
|---|---|
| 设置页显示"服务端离线" | BFF 未启动：`bash start.sh`（或 `python3 server.py 8801`） |
| 密钥保存后引擎芯片未变"就绪" | 检查 `data_server/` 目录可写（config.json 写入失败会静默降级本机模式） |
| 大模型测试"服务端代理无法连接" | 目标服务不可达或 Base URL 有误；Mock 桩仅限开发（tools/mock_llm.py） |

## 八、数据库：SQLite / MySQL 双后端（V1.1 新增，已实测）

留痕与归档的存储层为**双后端适配器**（`server.py` 存储层，接口同构、前端无感知）：

| 后端 | 适用场景 | 特点 |
|---|---|---|
| SQLite（默认） | 演示、试点、单机 | 零依赖、单文件（`data_server/medagent.db`，WAL 模式）；**迁移=拷贝 `data_server/` 目录**；已开 WAL 与 busy_timeout，断电不丢已提交事务 |
| MySQL | 生产、多终端并发、医院信息科统一运维 | 标准备份/主从/账号权限体系；驱动 pymysql 已随项目打包于 `vendor/`（纯 Python，**无需 pip 安装**） |

### 8.1 后端选择与切换

优先级：环境变量 `MEDAGENT_DB_BACKEND=mysql|sqlite` > `data_server/config.json` 的 `db` 节 > 默认 sqlite。

```json
{ "db": { "backend": "mysql",
          "mysql": { "host": "127.0.0.1", "port": 3306,
                     "user": "medagent", "password": "***", "database": "medagent" } } }
```

- `config.json` 含 MySQL 密码，权限 0600（保存配置时自动保持）；`GET /api/config` 永不下发；
- 存储后端属运维配置，浏览器"系统设置"页不可改（防止越权选择存储位置）；
- MySQL 连不上时 server.py **启动即失败并给出原因**（fail-fast，不静默降级到 SQLite——避免误以为在写库）。

建库语句参考：

```sql
CREATE DATABASE medagent CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'medagent'@'localhost' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON medagent.* TO 'medagent'@'localhost';
```

### 8.2 SQLite → MySQL 迁移（一次性/幂等）

```bash
python3 tools/migrate_sqlite_to_mysql.py                 # 目标库参数读 config.json 的 db.mysql 节
python3 tools/migrate_sqlite_to_mysql.py --dry-run       # 只统计不写库
python3 tools/migrate_sqlite_to_mysql.py --host 1.2.3.4 --user medagent --password *** --database medagent
```

- `archives` 按 id REPLACE（重跑覆盖）；`audit_logs` 按内容四元组去重（重跑不重复、不漏行）；
- 迁移后把 `db.backend` 改为 `"mysql"`（或设环境变量）重启即切换；回退同理改回 sqlite。

### 8.3 备份与恢复

```bash
python3 tools/backup_db.py              # 按当前后端备份到 data_server/backups/
python3 tools/backup_db.py --keep 30    # 默认保留最近 14 份
```

- SQLite：在线备份 API 快照（服务运行中可执行，WAL 安全）；
- MySQL：`mysqldump --single-transaction` + gzip（密码经 `MYSQL_PWD` 环境变量传递，不出现在进程列表）；
- 建议 crontab（每日凌晨）：
  `30 2 * * * cd /opt/medagent && /usr/bin/python3 tools/backup_db.py >> data_server/backups/backup.log 2>&1`
- 恢复：SQLite 用备份 .db 覆盖 `medagent.db`（先停服）；MySQL `gunzip -c 备份.sql.gz | mysql -u medagent -p medagent`。

### 8.4 与"服务器可迁移"的关系（部署形态约定）

| 环境 | 推荐形态 | 搬家方式 |
|---|---|---|
| 开发/演示机（如本机） | SQLite | 拷贝 `medagent/` 整目录（含 `data_server/`） |
| 医院云服务器（生产） | MySQL（信息科已有实例则直接用） | `migrate_sqlite_to_mysql.py` 一次导入 + `db.backend="mysql"` |
| 两台服务器间 | 同后端 | SQLite 拷目录；MySQL 用 mysqldump 导出导入（8.3） |

故障排查追加：

| 现象 | 处置 |
|---|---|
| 启动报"MySQL 连接失败" | 按提示核对 host/port/user/password/database；`mysql -u medagent -p -h <host> medagent -e "SELECT 1"` 验证 |
| 启动报"未找到 pymysql" | 保留项目 `vendor/` 目录（驱动已随包提供）；勿只拷贝 server.py |
| `/api/health` 的 `db.backend` 与预期不符 | 环境变量 `MEDAGENT_DB_BACKEND` 优先于 config.json，检查是否残留 |

## 九、云服务器部署（deploy/ 套件，V1.2 新增）

三种部署路径与完整上线检查单见 **`deploy/README.md`**，套件文件：

| 文件 | 用途 |
|---|---|
| `deploy/Dockerfile` | 生产镜像（零第三方依赖，pymysql 随 vendor/ 打包；非 root 运行；自带健康检查） |
| `deploy/docker-compose.yml` | 一键编排：应用 + 可选 MySQL 8 + 可选 nginx（数据卷持久化 data_server/） |
| `deploy/nginx.conf.example` | TLS 终结 + 基础认证/IP 白名单示例（公网部署必须 HTTPS：浏览器麦克风权限要求安全上下文） |
| `deploy/medagent.service` | systemd 单元（内置 NoNewPrivileges/ProtectSystem 加固，仅 data_server/ 可写） |

要点：
- **多终端适配已内置**（H5 响应式）：≥1920 大屏放大、≤900 双卡堆叠、≤768 手机底部导航 + 安全区适配，手机/平板/电视均可直接使用，无需单独 App；
- **上线前自检**：系统设置 → ④ 接入自检 → 全绿为准（BFF/数据库/ASR 签名/大模型连通/数据层，未登记项显示"待交付"）；
- **外部资源对接**：按《docs/接入准备清单.md》交付 ASR Key / 大模型配置 / HIS 接口，登记后自检面板即时反映就绪状态。
