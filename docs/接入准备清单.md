## 一、ASR 语音识别引擎（外部依赖 #1）

### 1.1 主用：科大讯飞（通道已按官方协议接通，等 Key 即通）

| 事项 | 说明 |
|---|---|
| 开通地址 | https://console.xfyun.cn （注册 → 实名认证） |
| 需开通的服务 | **实时语音转写（rtasr）**——注意不是"语音听写（iat）"，两个是不同服务 |
| 需要交付的三项 | `appId`、`apiKey`、`apiSecret`（控制台 → 我的应用 → 服务接口认证信息） |
| 套餐 | 实时转写时长包（**试用/体验包即可先做选型测试**，正式量按比选结果采购） |
| 可选 | 方言增强包（山东话识别能力在控制台按需开通，用于方言场景实测） |

**交付方式（二选一）**：
1. 把三项发我，我在服务器端登记（`data_server/config.json`，0600 权限，浏览器不落明文）；
2. 或管理员账号登录系统 → 系统设置 → ① 方言语音识别引擎 → 选"科大讯飞"填入三项 → 保存。

**给之后立即发生**：录音页"科大讯飞"芯片变"密钥就绪"→ 选中后点录音即走真实 WS 转写（医疗领域 pd=medical + 近场模式已内置）。

**我方验收流程**：
1. 真实麦克风录音 → 实时转写文本出现 → 生成链路自动以"真实转写 + 病案文书"为素材；
2. 评测页登记的 **5 组真实门诊音频**（1–5.m4a）做四维比选：字准率 / 医疗术语与热词表现 / 实时时延 / 单价成本——产出选型结论交院方拍板。

### 1.2 备选：阿里云智能语音交互（同口径比选用）

| 事项 | 说明 |
|---|---|
| 开通地址 | https://nls-portal.console.aliyun.com |
| 需要交付 | `appKey` + AccessKey `ID/Secret`（或确认用 Token 方案） |
| 当前状态 | 接口位已预留；Token 流程与 WS 通道待挂接（讯飞先通后按同口径补齐） |

> 比选策略（方案 4.2）：讯飞先实测，阿里同口径补测，产出对比报告后定主用引擎，另一家留作备选。

## 二、大模型 API（外部依赖 #2）

### 2.1 过渡方案：云端 API（推荐先走，不等 GPU）

| 事项 | 说明 |
|---|---|
| 形式要求 | **OpenAI 兼容接口**（提供 `/v1/chat/completions` 与 `/v1/models` 即可） |
| 需要交付的三项 | `baseUrl`（如 `https://open.bigmodel.cn/api/paas/v4`）、`apiKey`、`model` 名称 |
| 国内候选 | 智谱 GLM / 通义千问 qwen-plus / DeepSeek 等（合规云，具体由院方认可决定） |
| 私有化（二期） | 方案 4.3.3：8 卡 GPU 私有化部署；届时同一配置位改 baseUrl 即切换，代码不动 |

**交付方式**：管理员账号 → 系统设置 → ② 大模型 API → 填三项 → 保存 → 点"测试连接"（走服务端代理，无 CORS）。

**给之后立即发生**：生成引擎处于"自动"模式（默认），服务端配置就绪即**自动切换为大模型草稿**——字段级书写要求 + JSON 结构化输出已就绪；任何失败自动回落规则引擎，接诊不中断。

**我方验收流程**：
1. 金标准评测（闫秋荣真实住院）同口径复测：入院 64% / 首次病程 60% / 出院 50% 可用率（规则引擎基线）→ 迭代提示词至**首次病程 ≥85%**（M2.2 目标）；
2. 逐字段对照报告导出，交研发/医务科评审。

### 2.2 数据合规确认项（送云端前需院方拍板）

- 哪些患者字段允许送云端大模型？（建议：仅问诊对话转写文本，且经系统脱敏开关处理姓名）
- 是否要求"数据不出院"？（是 → 直接走私有化路线，过渡期仅用合成/脱敏数据调试）

## 三、HIS / EMR 接口（外部依赖 #3，院方信息科）

### 3.1 需要交付的三样

1. **接口文档**（含鉴权方式、地址、出参样例）；
2. **测试环境地址 + 测试账号**（或测试数据导出权限）；
3. **数据字典**（字段名/编码表，尤其 ICD、科室、药品字典）。

### 3.2 接口优先级清单（按系统用途排序）

| 优先级 | 接口 | 用途 |
|---|---|---|
| P0 | 患者基本信息（按门诊号/住院号/病案号查询） | 接诊第一步"患者核对"（蓝色 HIS 带入） |
| P0 | 检验结果（含参考范围、H/L 异常标识） | 数据汇聚智能体 + 辅助检查字段 |
| P1 | 检查报告（影像 IMPRESSION） | 辅助检查字段 |
| P1 | 医嘱（在院 + 历史） | 用药相关文书生成 |
| P2 | 生命体征 | 蓝色客观字段 |
| P2 | 患者就诊记录列表（历次住院/门诊） | 患者画像跨住院次汇聚 |

### 3.3 可接受的数据形态（按接入速度排序）

| 形态 | 接入方式 | 说明 |
|---|---|---|
| ① REST API | BFF 对接层直连 | 最优；按《接口与字段映射说明.md》联调四步走 |
| ② 数据库只读账号/视图 | 我方定时拉取 | 需信息科开只读权限 |
| ③ 定期导出文件（xls/xml/zip） | `tools/build_data.py` 流水线 | **现有流水线已支持此形态**（当前 5 位真实患者数据即此方式接入），最快见效 |

### 3.4 我方验收流程（联调四步）

接口文档核对 → 逐字段映射核对（对照 `docs/接口与字段映射说明.md`）→ 金标准回填验证（同一患者接口数据 vs 病案原文一致性）→ 验收报告。

## 四、部署与安全配套（需要拍板/提供）

| # | 事项 | 需要什么 | 建议 |
|---|---|---|---|
| 1 | 云服务器 | 一台 Linux 主机（2C4G 起，无需 GPU；Ubuntu/CentOS 均可） | 演示与试点共用；数据盘 ≥40G |
| 2 | MySQL | 院方已有实例则给账号（host/user/password/database）；没有则我方容器自建 | 生产建议院方实例，进信息科备份体系 |
| 3 | 域名 + HTTPS | 院内域名一条 + 证书（Let's Encrypt 免费证书或院内 CA） | 涉及麦克风权限，**浏览器要求 HTTPS 或 localhost**——公网部署必须 HTTPS |
| 4 | 访问控制 | 明确访问范围：仅院内网 / VPN / 公网+认证 | 试点期建议院内网 + IP 白名单；公网须加认证层（部署套件已备 nginx 认证示例） |
| 5 | 备份策略 | 确认备份窗口 | `tools/backup_db.py` + crontab 每日自动备份，保留 14 份 |
| 6 | 演示合规 | 确认对外演示范围 | 系统自带脱敏开关（一键化名）；演示数据含真实病历，禁止公网裸奔 |

## 五、"给我之后会发生什么"——接入动作对照表

| 资源交付 | 我方动作（≤30 分钟） | 界面表现 | 验收动作 |
|---|---|---|---|
| 讯飞三项密钥 | 设置页登记 | 录音页芯片"密钥就绪" | 真录音转写 + 5 组音频比选报告 |
| LLM 三项配置 | 设置页登记 + 连通测试 | "测试连接"成功，生成引擎自动切换 | 金标准同口径复测报告 |

> 数据一到 → 设置页登记 → 自检面板全绿 → 直接进入实测，**没有第二次开发**。
