## 二、结论：选择千问 qwen3.8-max（关闭思考）作为默认生成引擎

1. **质量第一**：13/15 事实覆盖居首；方言否定句把握是决定性优势——"否认药物过敏史""育有2个男孩"两处 DeepSeek 全系丢失（过敏输出空串、婚育漏字段），千问 3/3 轮稳定命中。录音转写场景的问诊类字段恰以这类方言对话为核心素材。
2. **工程指标全面占优**：3.9s 时延（演示节奏友好）、0.841 轮间一致性（结果最可复现）、出 token 133（成本约 DeepSeek think 的 1/40）、零编造零泄漏。
3. **DeepSeek 定位为备份**：v4-pro(think) 质量接近（12.7）但 58s 时延 + 5352 出 token，作复杂案例备用通道；deepseek-flash(fast) 1.8s 作轻量兜底。三家均已注册 `llmProviders`，切换=改一行配置。
4. **千问 think 模式禁用**：95s+ 且 2/3 轮超时，已在配置固定 `thinking: off`（DeepSeek 端点同样支持该参数，本轮改造一并支持）。

## 三、选型有效性说明

- 两家端点同为 Anthropic Messages 格式，经同一套 BFF 归一化代码接入，**提示词、素材、温度、评分完全同源**，排除了口径差异；
- 事实清单 15 项全部可溯源（转写对话或 HIS 客观要素），硬编造清单为素材不存在项（"转移性"、术后病理入入院记录、具体日期等）；
- 端点存疑项：千问截图域名 `maas.qianwenaiaip.com` 公网不存在，实测 Key 命中百炼官方端点 `dashscope.aliyuncs.com/apps/anthropic`。若该地址实为私有中转面板，需提供正确域名后重跑本测试复核。

## 六、产品链路落地验证记录（2026-10-24，qwen3.8-max 激活态）

**入院记录全链路（真实浏览器 IAB 实测）**：登录→房传虎→上传若雨双重验证转写→六智能体（"生成引擎：大模型草稿，改写 6/8 字段"）→四色核对→医师补录婚姻史（"医师已修改"）+专科情况知情留空→签名归档→MD+XML。XML 2407 字节，9 项校验全过（医师修改值不被 AI 覆盖、无术后病理时序污染、SourceNote 溯源、问诊转写附注、签名齐备）。留痕：audit_logs 八步全入库 + archives 批次 AR81873167（MD 3940 字符，MySQL）。

**首次病程/出院记录（Node 直驱产品同路径，tools/fcdc_node_check.mjs，9 项断言全过）**：
