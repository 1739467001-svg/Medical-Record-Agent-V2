## 一、系统是什么

**东阿县人民医院 AI 病历智能体的医生端网页系统**：医生选择患者 → 医患对话录音（方言实时转写）→ 六智能体流水线自动起草结构化病历 → 分色确认（AI 内容必须经医生核对）→ 签名归档生成 Markdown 病历 → 跨住院次患者画像 → 金标准量化评测。覆盖住院（入院记录/首次病程/出院记录）与门诊两类场景。

**贯穿全系统的设计哲学：演示态与生产态同构。** 任何真实能力（大模型生成、云端语音转写）都先用确定性规则引擎跑通全链路，真实引擎到位后**原位替换**——数据结构、接口、界面完全不变。因此"外部资源到位后 30 分钟接入实测"不是口号，而是架构保证：登记密钥 → 设置页自检变绿 → 直接实测，没有第二次开发。

**另一条铁律：零编造。** 系统不含任何 AI 编造的病史、对话或转写文本——数据层全部程序化提取自院内真实病案（README 有声明），缺数据就留空高亮（黄色），绝不虚构。

## 三、实现原理（六条核心链路）

### 3.1 前端：为什么是无框架 SPA

`index.html` 里只有一个 `<div id="app">`，`app.js` 按 `state.view` 切换视图并用模板字符串重渲染。**不用 React/Vue 的理由**：医院服务器给一个目录就要能跑（不装 Node、不构建）、代码可被院方完全审计（47 个入库文件中零外部依赖）、不会因第三方包停维而失联。代价是手写视图函数，收益是整个前端任何工程师一上午能读完。会话恢复：接诊进度存 `sessionStorage`，刷新不丢；留痕/归档**双写**（localStorage + 服务端 SQLite），启动时按 id/四元组去重合并，BFF 离线自动降级本机模式（界面明示）。

### 3.2 六智能体流水线：编排器 + 溯源协议

`agents.js` 的 `runPipeline` 是顺序泵：按 1250ms/步的节奏可视化执行（可快进），每步产出 `{summary, detail, fields}`。核心在**字段结构**——每个字段携带：

| 属性 | 含义 |
|---|---|
| `source` | 蓝=HIS 带入 / 绿=对话提炼 / 灰=规范所见 / 黄=缺失待补（方案 2.2 四色） |
| `evidence` | 数据出处（病案文书原文 / HIS 字段 / 转写来源），悬浮可查 |
| `confidence` | 置信度（0–1），界面显示百分比 |

**四色不是 UI 装饰，是贯穿数据层的溯源协议**：质控智能体检查黄色未处理字段 → 归档硬拦截（不臆造原则的机制化）；医生双击可改字段，修改自动标记"医师已修改"并进入留痕。

### 3.3 生成智能体：双态 Provider（llm.js）

1. **规则引擎先行**：同步算出"底稿"（确定性、可复现，也是评测基线）；
2. **LLM 并行增强**：每类文书一次请求，字段级书写要求（含金标准原文作文风样例），要求模型返回 `{字段id: 文本}` 的 JSON；
3. **安全合并**：解析成功后只覆盖"非空且可改写"的绿/灰字段——**HIS 客观字段（蓝）与黄色待补项永远不被模型触碰**；不臆造铁律写入系统提示词；
4. **永不阻断**：未配置/离线/超时 40s/返回无法解析 → 整体回落规则底稿，接诊流程照常完成；
5. **自动生效**：设置页"生成引擎：自动"（默认）下，服务端大模型配置就绪即切换，无需改代码。

### 3.4 语音：可替换 ASR 模块 + 签名不出服务器

四个引擎位（方案 4.2 可替换设计）：演示引擎 / 浏览器引擎（Web Speech API，真实麦克风普通话）/ **讯飞（真实 WS 通道，已按官方协议实现）** / 阿里（接口位，Token 流程待挂接）。

讯飞通道（`rtasr.js`）：AudioWorklet 采集麦克风 Float32 → 线性重采样 16k/16bit 单声道 → 每 640 采样（40ms/1280 字节）一帧 → `wss://rtasr.xfyun.cn/v1/ws` 上行（`started` 前缓存防竞态）→ 回包 `action=started/result/error` 解析（result.data 二次 JSON 解析，`st.type` 0=终稿/1=中间）→ 结束发送 `{"end": true}` 帧等服务端回完终稿断开；启用 `pd=medical`（医疗垂直领域）+ 近场模式。**鉴权签名由 BFF `/api/asr/sign` 计算**（官方算法：`base64(HmacSHA1(key=apiKey, msg=MD5hex(appid+ts)))`，曾修正过一处漏 MD5 的实现错误），密钥明文永不出服务器。

### 3.5 存储：适配器双后端

SQLite/MySQL 实现**同一套接口**（add_audit / put_archive / list...），环境变量 `MEDAGENT_DB_BACKEND` 或 config.json 的 `db` 节一行切换：

- **SQLite（默认）**：单文件 + WAL 模式（断电不丢已提交事务），是"我的服务器 → 医院云服务器"迁移性最好的形态（拷 `data_server/` 目录即搬家）；
- **MySQL（生产）**：接入医院信息科现成的备份/主从/账号权限体系；驱动 pymysql（纯 Python）随项目打包于 `vendor/`，**服务器不需要 pip 安装任何东西**；
- 配套 `tools/migrate_sqlite_to_mysql.py`（幂等迁移）与 `tools/backup_db.py`（每日定时备份，保留 14 份）。

### 3.6 质量闭环：金标准评测（eval.js）

以闫秋荣 2023-11 真实住院为金标准（医生手写原文，21 份完整文书全集），系统用同源素材生成入院/首次病程/出院三类草稿，与医生原文**逐字段对照**（字符级 bigram F1：≥0.85 一致 / 0.6–0.85 基本一致 / <0.6 偏差），产出覆盖率、平均相似度、可用率与改进项，报告可导出 MD。**当前规则引擎基线：入院 64% / 首次病程 60% / 出院 50% 可用率**——这是大模型接入后"同口径复测"的对照基线（M2.2 目标：首次病程 ≥85%）。

## 五、安全与合规设计（"约法三章"的工程落地）

1. **人在回路**：AI 只产草稿，签名归档的责任主体始终是医生；黄色缺失项未处理则质控**硬拦截**归档，医生补填或"确认留空"（留空也进留痕）。
2. **不臆造**：三道闸——① 数据层零编造（全部程序化提取自真实病案 zip 与 HIS 导出）；② 生成层缺数据留空高亮、LLM 只能改写有据字段；③ 交互层医生确认才归档。
3. **全程可追溯**：登录/录音/生成/修改/留空/归档全操作写留痕（本地 + 服务端 SQLite 双写），审计页可查可导出；留痕含操作人、时间、内容摘要。
4. **密钥治理**：ASR/大模型/数据库凭证只存服务器 `data_server/config.json`（0600），浏览器仅持"已配置"布尔标记；`GET /api/config` 只返回掩码状态；存储后端为运维级配置，浏览器不可改。
5. **部署边界**：演示数据含真实患者信息，**禁止公网裸奔**；公网必须 HTTPS（麦克风权限的浏览器硬性要求），deploy/ 套件已备 TLS + 基础认证 + IP 白名单配置示例；数据备份脚本 + crontab 就绪。

## 六、真实数据边界（诚实声明）

**已被真实环境验证的**：
- 存储双后端：本机 MySQL 8.0 真库端到端（写入/回读/迁移幂等/双模式备份）；
- 讯飞 WS：真实握手——讯飞服务器返回标准协议错误（10105），证明 URL/鉴权/回包解析/错误链路全部正确；
- LLM 传输链路：mock 桩（OpenAI 兼容）全链路 + 失败回落两态；
- 数据层：187 份真实病案文书全文可直接阅读。

**等待外部资源后才能验证的**（接口全部就绪，见《接入准备清单.md》）：
- 讯飞真实转写质量（等 Key）→ 届时用 5 组真实门诊音频做四维比选（字准率/热词/时延/成本）；
- 真实大模型生成质量（等 Key）→ 金标准同口径复测；
- HIS 正式接口联调（等院方接口文档）。

**明确不做的**（正式版范围）：真实 HIS 直连（现用真实导出数据模拟）、GPU 私有化部署（方案 4.3.3，二期）、原生 App（H5 已适配移动端，App 属 P2 后段）。

## 七、设计决策与取舍记录（为什么这么做）

| 决策 | 得到什么 | 放弃什么 / 应对 |
|---|---|---|
| 前端无框架、无构建 | 零依赖可部署、全代码可审计、永不受 npm 生态牵连 | 手写视图函数（app.js 较大）；用清晰的模块划分弥补 |
| 后端仅 Python 标准库 | 医院服务器零安装；server.py 400 行可人工审完 | 无异步/无 ORM——当前规模（院内几十并发内）不构成瓶颈，真到规模再换 FastAPI 不迟 |
| SQLite 默认 + MySQL 可选 | 迁移最简（拷目录）与生产运维（信息科体系）双形态兼顾 | 需要维护两套适配器——接口同构后代码增量很小 |
| 演示态规则引擎同构先行 | 全链路日日可演示、评测有确定性基线、外部资源到位零返工 | 规则引擎生成质量有限（可用率 64%/60%/50%）——这正是评测模块要量化并迭代的对象 |
| 留痕双写（本地+服务端） | 离线可演示、在线可审计 | 去重逻辑按 id/四元组，极端时钟错乱场景可能重复——审计场景可接受 |
| H5 响应式而非原生 App | 一套代码覆盖手机/平板/大屏/桌面 | 不支持离线推送/深度相机等原生能力——方案里 App 本就属二期 |

## 九、扩展指南（后续开发者怎么动它）

**加一种文书类型**（如"术前小结"）：
1. `js/agents.js`：新增 `runGenerateSS(patient, admFields)` 产出同构字段数组（source/evidence/confidence），在编排器 `rulesFabrics` 与 `applyGeneration` 挂接；
2. `js/app.js`：`CONSULT_DOCS.ipd` 增加页签项；
3. `js/md.js`：新增 `buildSSMD()`（字段对齐院内模板）；
4. 有金标准则同步扩展 `eval.js` 对照组。

**加一个 ASR 引擎**：`js/asr.js` 的 `ASR_ENGINES` 注册 → `js/config.js` 的 `asrConfigured` 增加判定 → `server.py` 的 `/api/asr/sign` 增加签名分支 → 新建 WS 客户端模块（照 `rtasr.js` 的结构：取签名→getUserMedia→分帧→回包解析→onProgress/onError/onDone 同构回调）→ `app.js` 的 `startASR` 增加分支。

**切换数据库**：环境变量 `MEDAGENT_DB_BACKEND=mysql` 或 `config.json` 的 `db` 节 → 重启即生效；历史数据用 `tools/migrate_sqlite_to_mysql.py` 幂等迁移；`tools/backup_db.py` 双模式通用。

**重建数据层**（改了解析逻辑后）：`python3 tools/build_data.py`（重建 js/data.js，读 `../病历资料/`）+ `python3 tools/export_records.py`（重建 data_records/）。**这两个文件勿手改**——它们是"零编造"的证据链。

**日常运维**：`bash start.sh`（8801）→ `/api/health` 健康检查 → 设置页"接入自检"一键体检 → `tools/backup_db.py` 备份。详见《部署运维手册》。

## 十一、常见问题（FAQ）

**Q1：双击 index.html 打不开？**
页面是 ES Modules，必须经 HTTP 访问。`bash start.sh` 后打开 http://localhost:8801 。

**Q2：密钥保存后输入框为什么是空的、显示"已配置"？**
密钥明文只存服务器且**永不回显**——留空表示"保持服务器现有值"，防止泄露。

**Q3：大模型挂了/没配置，系统能用吗？**
能。任何失败自动回落规则引擎，接诊/归档/导出全流程不中断；界面明示当前生成引擎。

**Q4：数据存在哪？会丢吗？**
会话进度在浏览器 sessionStorage；留痕/归档双写本地与服务端 `data_server/`（SQLite/MySQL）。清浏览器缓存不丢服务端数据；服务器迁移拷目录或跑迁移工具。

**Q5：演示数据能外传吗？**
**不能。** 全部数据含真实患者信息，仅限研发验证；对外演示必须开启脱敏开关（姓名化名，仅展示层替换）且限定受众。

**Q6：手机/平板能用吗？**
能。H5 响应式已适配手机（底部导航）/平板/大屏/电视，浏览器直接访问同一地址。

**Q7：怎么验证 AI 没有瞎编？**
三道机制：字段级来源溯源（evidence 悬浮可查）+ 黄色待补强制处理 + 金标准逐字段量化评测（报告可导出复核）。
