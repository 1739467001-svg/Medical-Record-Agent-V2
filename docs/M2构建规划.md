## 一、为什么还有"现在就能建"的工作

M1.x 阶段为快速演示做了三个**演示态妥协**，它们恰是 M2 的工程前置：

| 演示态妥协 | 问题 | M2.0 目标态 |
|---|---|---|
| ASR/LLM 密钥存浏览器 localStorage | 医院级安全不可接受（约法三章 #1） | 密钥仅存服务器（BFF），浏览器只持"已配置"标记 |
| 留痕/归档存 localStorage | 清缓存即丢，不满足审计要求 | SQLite 入库，前端写后即报、启动即拉 |
| 浏览器直连大模型（CORS 受限、密钥暴露） | 不可用于真实调用 | 服务端代理 `/api/llm/chat`，密钥不出服务器 |

## 二、任务分解

**S1 服务端 BFF（关键路径，本轮实施）**
新增 `server.py`（仅 Python 标准库，便于院内部署）：
- 静态资源托管（替代 `python -m http.server`）；
- `POST /api/audit`、`GET /api/audit`、`POST /api/archives`、`GET /api/archives` → 数据库（`data_server/medagent.db`）；
- **存储层双后端（V1.1 升级，已实测）**：SQLite 默认（零依赖、单文件可迁移、WAL）+ MySQL 可选（pymysql 随项目打包于 `vendor/`，面向生产与医院信息科运维）；切换经 `config.json` 的 `db` 节或环境变量 `MEDAGENT_DB_BACKEND`；配套 `tools/migrate_sqlite_to_mysql.py`（幂等迁移）与 `tools/backup_db.py`（定时备份）；详见《部署运维手册》第八章；
- `GET/POST /api/config`：服务端密钥配置（`data_server/config.json`，权限 0600），GET 仅返回**掩码状态**（是否已配置、appId/appKey 等非敏感项），密钥明文永不下发；
- `POST /api/llm/test`、`POST /api/llm/chat`：服务端代理（OpenAI 兼容），顺带消除浏览器 CORS 限制；
- `POST /api/asr/sign`：讯飞实时转写的 HmacSHA1 签名在服务端计算（纯算法，可离线向量自测）；阿里云 Token 流程 M2.1 挂接。

**S2 前端同步层（本轮实施）**
新增 `js/sync.js`：启动时 `/api/health` 探测 → 在线则拉取合并服务端留痕/归档（按 id 与四元组去重）；`audit()` 与归档后异步上报（失败静默，不影响本地演示）。服务端离线自动降级为现有本机模式——**双模式共存，拔掉服务器也能演示**。

**S3 配置台升级（本轮实施）**
设置页切为服务端模式：保存即 `POST /api/config`；密钥输入框**不再回显明文**（占位符提示"已配置，留空保持不变"）；"测试连接"走服务端代理；页头显示服务端在线状态与存储位置。

**S4 Mock 实测（本轮实施）**
`tools/mock_llm.py`（OpenAI 兼容桩）：验证 `设置页 → /api/llm/test → BFF 代理 → 桩` 全链路连通；讯飞签名用已知向量自测；SQLite 持久化用"入库 → 清浏览器缓存 → 重启仍可读"验证。

**S5 生成智能体替换（M2.1，需真实模型）——传输/解析/回落骨架已就绪（2026-10-05 实测）**
`js/llm.js` Provider 已实现并接入流水线：每类文书一次请求、字段级书写要求（含金标准文风样例）、JSON 结构化输出（稳健解析，容忍代码块包裹）、**仅覆盖非空可改写字段**（HIS 客观字段/黄色待补字段永不被模型触碰）、任何失败（未配置/离线/超时 40s/返回非 JSON）**整体回落规则引擎**不阻断接诊。设置页新增"生成引擎：自动/规则演示"开关（默认自动——服务端登记 Key 即生效，无需改代码）。mock 桩已升级为"回填 JSON 模板"以实测解析链路（MOCK_LLM_FAIL=1 可测回落）。**剩余（Key 到位后）：按字段分提示词调优 + 金标准同口径复测**（当前规则基线：入院 64% / 首次病程 60% / 出院 50% 可用率）。

**S6 ASR WS 通道（M2.1，需真实密钥）**
`/api/asr/sign` 就绪后，浏览器端麦克风采集（AudioWorklet→PCM）+ WS 上行 + 热词表注入；以评测页登记的 5 组真实音频做离线选型测试（方案 4.2 四维）。

**S7 医学实体级评测（M2.2）**
评测算法从 bigram F1 升级：诊断/药品/生命体征按结构化实体比对，作为风格对齐迭代的更准标尺。

**真实基线（2026-10-03，规则重组引擎，已替换原手写模拟稿口径）：**入院 64% / 首次病程 60% / 出院 50% 可用率。M2.1 真实大模型接入后同口径复测，提升幅度以此为准。

**S8 HIS 联调（M3，需接口文档）**
按《接口与字段映射说明》执行：联调清单四步（接口文档→字段核对→金标准回填→验收）。

## 四、安全姿态升级（约法三章 #1 落实）

1. 密钥明文只存在于服务器 `data_server/config.json`（0600），浏览器与日志中不出现；
2. 审计/归档落数据库：SQLite 默认（WAL 断电安全）或 MySQL 生产后端，定时备份脚本 `tools/backup_db.py`，满足"全程可追溯"；
3. 大模型/ASR 调用全部经 BFF 出口，院内网络只暴露 8801 一个端口；
4. MySQL 凭证仅存服务器 config.json（0600）；存储后端为运维级配置，浏览器不可改；
5. 后续（正式版）：BFF 加鉴权 Token、按角色最小权限、HTTPS（方案 4.5）。
