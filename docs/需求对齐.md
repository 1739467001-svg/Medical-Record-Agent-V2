## 一、三个信息源的对齐结论

### 1.1 口述场景（用户）→ 方案条目映射

| 口述需求 | 规划方案对应条目 | 对齐结论 |
|---|---|---|
| 医生打开系统/智能体接诊 | 3.1 产品形态：医生端 App + 网页端 | 本期交付**医生端网页端**（MVP），App 属一期 P2 后段/二期 |
| 听取患者症状描述 | 3.3 数据流第 2 步：一键录音→语音转写 | 录音入口内嵌在接诊流程，支持实时录音与演示音频两种模式 |

| 记录到 MD 文档 | 3.3 第 3 步：生成结构化病历草稿 | 病历以 **Markdown 结构化文档**落地（预览 + 可下载 .md），字段与院内模板一一对应 |

### 1.2 真实数据（病历资料）→ 系统输入形态确认

对 5 位住院患者（刘倩倩、张俊杰、荣玉民、闫秋荣、麻玉兰）共 12 人次住院的数据分析：

- **病案文书（zip 内 XML）**：XTextDocument 模板格式，含 `XInputField` + `DataSource/BindingPath` 字段绑定，验证了方案 2.3"字段约束"设计。住院全流程文书链为：
  `入院记录 → 首次病程记录 → 主治/副主任查房记录 → 用药记录 → 术前小结 → 手术记录 → 术后首次病程 → 出院记录`（手术病例），非手术病例无手术环节。
- **HIS 结构化数据（xls，SQL 导出）**：医嘱（ORDER_TEXT/ORDER_CLASS）、检验结果（含 H/L 异常标识）、检查结果（IMPRESSION）、生命体征——正是"数据汇聚智能体"的输入。
- **患者就诊轨迹**：同一患者多次住院（荣玉民 4 次、闫秋荣 3 次等），跨年度（2023→2026），验证"患者画像需跨住院次汇聚"的设计。
- **门诊数据**：McDex 系统截图（门诊病历结构：主诉/现病史/既往史/家族史/体格检查/诊断含 ICD-10）+ 医患对话 m4a 音频——门诊音频做 ASR 选型测试集，门诊场景界面留位。

### 1.3 综合得出的智能体形态（本次建站目标）

**一个面向医生、以住院·入院记录为首切场景的网页端病历智能体**，完整呈现方案 3.2 三层架构与 3.3 端到端数据流：

```
医生登录 → 选择/扫码患者(拉HIS蓝数据) → 一键录音(方言→普通话转写)
       → 六智能体流水线(抽取→汇聚→检索→生成→质控→映射)
       → 病历草稿分色确认(蓝/绿/灰/黄,黄色必核) → 确认签名 → 生成MD → 归档留痕
       → 患者画像(跨住院次时间轴汇总,导出MD)
```

四色含义（方案 2.2，全站统一）：
- **蓝** = HIS/系统自动带入（不依赖语音，不可臆造）
- **绿** = 医患对话/口述提炼（ASR 转写后由智能体组织成规范表述）
- **灰** = 规范所见与知识辅助（模板常规项，供医生核定）
- **黄** = 缺失待补（一律留空高亮，严禁臆造，医生必须处理后方可归档）

## 二、"约法三章"在本期开发中的落实

1. **医院级安全**：界面全程标注"演示环境"水印；所有 AI 生成内容必须经医生确认才能归档（人在回路）；黄色缺失项强制核对；每步操作写入留痕日志（本 MVP 存 localStorage，正式版入库审计）；正式版加密传输/存储、私有化部署按方案 4.5 执行。
2. **有来有回**：见第四节"待补充问题清单"，已列出需用户拍板的事项。
3. **面向医生的产品视角**：四色图例常驻、黄色项一键定位、方言→普通话对照可回听核对、MD 即时预览、字段来源（哪句话、哪条检验）悬浮可查——让医生"看得懂、敢确认、改得快"。

## 三、MVP 边界（本网页版做什么/不做什么）

**做**：登录、患者工作台（真实 5 患者数据）、接诊向导（患者核对→录音/演示转写→六智能体流水线可视化→分色草稿编辑→签名归档）、MD 病历导出、患者画像报告导出、审计留痕页、ASR 引擎切换演示。

**不做（正式版范围）**：真实 HIS 接口对接（待院方接口文档，见 4.2）、私有化大模型部署（8 卡 GPU，方案 4.3.3）、移动 App、门诊全场景、真实 ASR 引擎计费接入。
