## 二、测试口径（两份报告完全一致）

- **素材**：若雨的双重验证转写文本（`patient01录音文本.txt`：ASR 原文 + 纠错后）+ HIS 客观要素（申请单主诉"腹痛1天"、门诊诊断"阑尾炎"、CT 印象/所见、入院体征、8 项检验异常）。**入院时刻快照不含术后病理**（本次系统改造：时序分文书裁剪）。
- **提示词**：逐行复制自 `js/llm.js` 的 `DOC_SPECS.adm`（8 字段级书写要求 + 零编造铁律系统提示词），见 `tools/llm_compare_out/prompt.txt`。
- **模式**：`think`（默认推理，max_tokens 16384）与 `fast`（`thinking:disabled`，4096）各 3 轮，temperature 0.2。
- **评分**：15 项可核查事实（转写+HIS 双源）命中；硬编造（转移性/术后病理/具体日期等素材不存在项）；软编造（未明示排除项的模板"否认"句）；结构化稳定性（JSON 有效/泄漏标记）；时延；token；轮间一致性（bigram）。

## 四、字段质量分析

**现病史（v4-pro · think 代表轮，全文）：**
> 患者缘于昨天下午出现腹痛，伴恶心、呕吐2-3次，无发热。曾于当地诊所肌注药物（具体不详），疼痛暂时缓解，后于次日凌晨2时许腹痛加重。为求进一步诊治来我院。

时间线完整（起病→院外治疗→缓解→夜间加重→来院），数值准确，无编造，接近医生书写习惯。

**共性缺陷（两模型 × 两模式均出现，3/3 轮）：**
1. **过敏史输出空串**——转写明示"什么药物有过敏的吗？嗯，没有"，规范行为应为"否认药物过敏史"。DeepSeek 全系把明示否定当作"无信息"（过度保守）。产品层无碍：mergeFields 只覆盖非空规则值，规则引擎已产"否认药物过敏"，LLM 空串时自动保留规则值。
2. **婚育史丢失"育 2 子"**——方言"几个孩子，两个男孩"未被提炼（flash fast 3/3 漏；v4-pro think 1/3 轮漏）。

**其它**：v4-pro · fast 首轮 42.5s 离群时延（后续 5.6~7.7s），演示场景需注意冷启动；无 COT 泄漏、无 markdown 包裹，JSON 纪律好。

## 六、结论

- DeepSeek 两模型**零硬编造、结构化纪律好**，质量上限高（v4-pro think 12.7/15）；
- 但 **v4-pro 时延 58s** 演示节奏偏慢、出 token 5352 成本高；**方言否定句把握弱**（过敏史/婚育史两处稳定丢分）；
- 定位建议：`deepseek-v4-pro(think)` 作**备用复杂案例通道**，`deepseek-flash(fast)` 作**轻量兜底**（1.8s/12 分）。两者均已注册在 `llmProviders`，切换无需改代码。
