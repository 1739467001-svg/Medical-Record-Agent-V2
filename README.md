# AI 病历智能体 · 医生端网页（MVP v0.1）

东阿县人民医院 AI 病历智能体系统的医生端网页演示版，对应《AI 病历智能体系统建设实施规划方案 1.0》一期 P1–P2 阶段：以**住院·入院记录**为首切场景，跑通"**选择患者 → 方言录音 → 多智能体生成 → 分色确认 → 签名归档 → 患者画像**"全链路。

## 启动

```bash
cd medagent
bash start.sh          # 默认 8801 端口，或 bash start.sh 9000 指定端口
```

浏览器打开 <http://localhost:8801>（需通过 http:// 访问，直接双击 index.html 无法加载 ES Modules）。

演示账号：**张岩**（普外科·副主任医师）/ **刘博**（神经内科·主治医师），点击即登录，无密码（MVP 演示用）。

## 核心设计（与规划方案逐条对应）

| 方案条目 | 系统落点 |
|---|---|
| 2.2 内容来源分色 | 蓝=HIS 带入 / 绿=对话提炼 / 灰=规范所见 / 黄=待补充（不臆造），全站统一图例 |
| 3.3 端到端数据流 | 接诊向导 5 步与方案流程一一对应 |
| 4.2 ASR 可替换 | 引擎抽象层 + 引擎切换 UI + 方言→普通话双轨转写对照 |
| 4.3.1 六智能体分工 | 流水线可视化，每个智能体展示结构化产出摘要 |
| 4.3.2 溯源与置信 | 每字段携带来源标签 + 置信度 + 证据（方言原声/转写/HIS 出处） |
| 3.4 人在回路 | 黄色缺失项未处理则**归档被质控拦截**；医师可补填或"确认留空" |
| 3.4 全程可追溯 | 登录/录音/生成/修改/留空/归档全操作写留痕（审计页可查，MVP 存 localStorage） |
| 口述需求"MD 文档" | 归档即生成 Markdown 病历（预览/下载/复制），字段与院内模板对应 |
| 口述需求"患者画像" | 跨住院次时间轴汇聚 + 画像报告 MD 导出 |
| 2.3 评测方法 | **金标准评测视图**：闫秋荣 2023-11 真实住院为金标准，六智能体生成**入院记录 / 首次病程 / 出院记录**三类文书草稿，逐字段对照（bigram F1），产出覆盖率/相似度/可用率与改进项，报告可导出 MD |
| 4.2 ASR 选型 | 评测页内置门诊 5 组真实音频测试集登记 + 引擎就绪状态，拿到 Key 即可按四维比选 |
| P4 多文书类型（预演） | 首次病程=由入院记录草稿多源汇聚；出院记录=手术/查房/评估文书汇聚，缺手术信息时自动转黄色待补 |
| M2 接入配置台（T15） | 系统设置页：讯飞/阿里密钥登记即就绪、大模型 API 连通性测试、脱敏与演示数据清理 |
| 数据安全（T12） | 顶栏"脱敏"开关：开启后所有界面与 MD 导出的患者姓名显示为化名，状态持久化 |
| 原始口述场景（T13） | **门诊接诊场景**：5 例整理自真实门诊截图（含 ICD 代码），方言→普通话双轨转写 + **真实原声回放**，生成门诊病历 MD（主诉/现病史/查体/西医诊断含ICD/中医诊断/诊疗意见）；诊断缺失时质控拦截 |

## 真实数据声明（零编造）

- `js/data.js` 由 **`tools/build_data.py` 程序化生成**（勿手改）：患者字段逐字取自病案 zip 内 XTextDocument XML；检验/医嘱取自 HIS SQL 导出 xls（按当前住院日期过滤）；门诊字段转录自真实门诊系统截图（含 ICD-10）。**系统不含任何 AI 编造的病史、对话或转写文本**——对话/转写待真实 ASR 引擎（M2.1）转写真实音频后填充，界面对此明示。
- `data_records/<患者>.json` 由 **`tools/export_records.py`** 提取：187 份真实病案文书全文，画像页"真实病案文书（原文）"查看器可直接阅读。
- 修改解析逻辑后重跑两个脚本即可重建数据层。**内部数据，请勿外传；对外演示前须脱敏。**

## 已验证链路

住院链路：登录 → 工作台 → 患者核对 → 录音/提前结束 → 双轨转写 → 六智能体（可快进）→ 四色草稿（**三文书页签**：入院/首次病程/出院分别核对与归档）→ 归档拦截验证 → 补填后签名归档 → MD 预览下载 → 患者画像 → 金标准评测（三类文书逐字段比对→指标→报告导出）→ 脱敏开关 → 留痕审计 → 刷新后会话恢复。

门诊链路（T13）：侧栏"接诊（门诊）"→ 门诊患者核对（门诊档案/慢病备案）→ 录音（真实原声回放 + 演示转写）→ 六智能体 → 门诊病历分色草稿（中医诊断黄色待补 → 确认留空）→ 签名归档 → 门诊病历 MD（结构对齐院内门诊模板）→ 画像页归档列表显示类型。

金标准评测基准（演示引擎，规则+模板生成）：

| 文书 | 覆盖率 | 平均相似度 | 可用率 | 暴露的改进项 |
|---|---|---|---|---|
| 入院记录（11 字段） | 100% | 81% | 73% | 主观病史模板改写与医生原文差异（真实基线；此前 64% 系体征字段丢失 bug，已修复） |
| 首次病程记录（5 字段） | 100% | 68% | 60% | 鉴别诊断/诊疗计划的本院书写风格对齐（M2.2 目标 ≥85%） |
| 出院记录（6 字段） | 100% | — | 50% | 文书汇聚字段（诊疗经过等）待手术记录数据源接入 |

实体级口径（M2.2 新增标尺）：实体召回率 95%（19/20）· 精确率 95%——漏报实体逐项点名（如"上腹部持续性绞痛"措辞差异），直接指出草稿没写到的事实。

评测页已明示：金标准=医生真实原文；待评测侧=规则重组引擎（M2.1 替换为真实大模型后同口径复测）。该工具面向研发/医务科，不面向接诊。


## M2.0 服务端模式（BFF）

- `bash start.sh` 默认启动 `server.py`（BFF）：留痕/归档入库、ASR/大模型密钥仅存 `data_server/config.json`（0600，浏览器不落明文），大模型连通性测试与调用经服务端代理（无 CORS）。
- **存储层双后端（已实测）**：SQLite 默认（零依赖、单文件、WAL；迁移=拷贝 `data_server/` 目录）；MySQL 可选（pymysql 随项目打包于 `vendor/`，无需 pip 安装）——切换经 `config.json` 的 `db` 节或环境变量 `MEDAGENT_DB_BACKEND`，配套 `tools/migrate_sqlite_to_mysql.py`（幂等迁移）与 `tools/backup_db.py`（定时备份，含 crontab 建议），见《部署运维手册》第八章。
- 前端新增 `js/sync.js`（启动合并 + 写后即报）与 `js/config.js` 服务端模式（`_srv` 就绪标记）；服务端离线自动降级本机演示模式。
- 开发专用桩 `tools/mock_llm.py`（8899，OpenAI 兼容）用于无真实模型时验证代理链路，生产禁用。
- 接口清单见 `docs/接口与字段映射说明.md` 第七章；运维（含数据库双后端）见 `docs/部署运维手册.md` 第七/八章。
